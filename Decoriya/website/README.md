# DEKORIYA / главная v6.7.1

[Сайт](https://oliverjone01-dev.github.io/turbium/Decoriya/website/) · [Карта анимации](https://oliverjone01-dev.github.io/turbium/Decoriya/website/motion-map.html) · [Figma desktop](https://www.figma.com/design/SsbOVLwLJnNFPwaeQ3bRqJ?node-id=109-1664) · [Figma mobile](https://www.figma.com/design/SsbOVLwLJnNFPwaeQ3bRqJ?node-id=109-2510)

Три новогодние растровые схемы: вход, витрина, интерьер. Каждый рисунок собран из трёх независимых проходов одного WebP: свет, декор и поверхности. При раскрытии свет уходит влево/вниз, декор остаётся посередине, поверхности — вправо/вверх. Проекция фиксирована. Движение выполняется через CSS translate/scale; Canvas, Worker и покадровый проигрыватель для этих схем больше не используются.

На мыши работает наведение и уход; на сенсорном экране — нажатие и повторное нажатие. Enter переключает, Escape собирает, фокус виден. При reduced motion положения переключаются мгновенно. Лёгкое собранное превью загружается при приближении к экрану. При первом взаимодействии загружается один атлас, перед раскрытием ожидается decode; повторное взаимодействие не скачивает изображения. Серии кадров нет.

Новый фон — тихая светлая студия разработки новогоднего декора. Хвоя, образцы бархата, украшения и фонарик находятся на дальнем рабочем столе справа. Лицо, основной портрет, отдельные кисти и непрерывный передний стол Олеси сохранены.

## Производительность и исходники

Для сайта используются атласы 1536×512, по 512×512 на проход. Один URL разделяется тремя CSS-плоскостями и кэшируется браузером. Большие варианты 2172×724 сохранены для макета и экспорта, но не выбраны текущей главной. Точные размеры — `assets/newyear-v66/assets.json`. Мобильный фон 960 px, десктопный 1672 px; остальная оптимизация 6.5 (WOFF2, адаптивные фото, отложенная галерея) сохранена.

PNG-мастера и промпты генерации находятся в рабочем пакете `landing-2026-11-12-v66`. Для кодирования: `python3 tools/build-newyear-assets.py --sources PATH_TO_MASTERS`. Скрипт только меняет размер и кодирование, сохраняя исходную альфу.

## Сборка и передача

- `python3 tools/check.py`
- `node --check motion.js` и `node --check motion-config.js`
- `python3 tools/package-wordpress.py`

WordPress: архив `wordpress/dekoriya-atelier-v671.zip`, тема `DEKORIYA Atelier Motion` 6.7.1, PHP от 8.0, WordPress от 6.6. Ресурсы и ссылки переводятся в путь темы при рендеринге. Загрузка галереи и CTA используют прежнюю логику.

Описание переходов берётся из `motion-config.js` и показывается в `motion-map.html`. История прежнего поворота камеры и его оптимизации сохранена в `docs/camera-history-through-v65.md`; она не описывает текущую механику трёх схем. Старые файлы рендера сохранены для ранее открытых страниц.

Сборка и проверка кода не заменяют визуальную проверку и реальные устройства. Фактический охват выпуска фиксируется в рабочем отчёте v6.6; проверка viewport в браузере не объявляется испытанием физических iPhone/Android.

## Исправления по аудиту v6.7 / 14.11.2026

Выбранный пример сохраняется в помощнике обращения с названием и ссылкой.
Страница фотографии поддерживает прямой вход и возврат с `?example=…`.
В WordPress просмотр использует маршрут `?dk_media=…` на реальной главной,
с проверкой допустимых идентификаторов. Название и описание главной заданы в теме.

На ширинах ≤1100 px действия стоят перед портретом. Критичные изображения hero
загружаются нативно без зависимости от app.js. Фокус сам не раскрывает схемы:
Enter/Space переключают, Escape собирает. Повтор после ошибки запускается одним
нажатием; превью остаётся видимым. Легенда отделена от кнопки и выдерживает переносы.
Для фотографий записаны фактические размеры и корректные srcset-дескрипторы.
Архив темы включает только используемые изображения и шрифты; CI проверяет
наличие актуального ZIP перед передачей артефакта.

GitHub Pages остаётся демонстрационной публикацией с `noindex,nofollow`.
Для WordPress индексируемость управляется настройками WordPress; поиск, домен,
аналитика и реальная доставка обращений требуют отдельной настройки запуска.

6.7.1: после выбора изображения мобильный просмотр переходит к блоку выбранного примера. Фокус не вызывает экранную клавиатуру. В результате помощника есть следующий шаг «Перейти к Олесе»; автоматической отправки нет.
