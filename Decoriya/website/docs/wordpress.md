# Установка и развитие на WordPress

1. В корне фронтенда выполнить `python3 tools/package-wordpress.py`.
2. На staging WordPress загрузить `wordpress/dekoriya-atelier-v4.zip` через «Внешний вид → Темы → Добавить → Загрузить» и активировать.
3. Установить русский язык сайта в общих настройках. В «Настроить → Декория: главная» изменить три строки hero и ссылку обращения. В текущей версии обращение открывает анкету Олеси на Профи.ру.
4. Проверить меню, галереи, исходник/ретушь, фильтр, контактное действие и мобильную компоновку. Не отключать индексацию на staging.

Тема: classic PHP, WordPress ≥ 6.6, PHP ≥ 8.0. Фактически открыта и проверена на WordPress 6.8 / PHP 8.3 в официальном Playground. `wp_head`, `wp_footer`, `wp_body_open`, title-tag, body classes и зависимости скриптов подключены. Пути изображений и JSON переписываются на URI темы. Шапка учитывает admin bar; ассеты получают версию по времени изменения. Интерфейс не зависит от Elementor, jQuery, GSAP, WebGL или внешних CDN.

Локальная повторная проверка через официальный npm-пакет:

```sh
npm exec --yes --package=@wp-playground/cli -- wp-playground-cli server --port=8770 --workers=1 --php=8.3 --wp=6.8 --blueprint="$PWD/tools/wp-blueprint.json" --mount="$PWD/wordpress/dekoriya-atelier:/wordpress/wp-content/themes/dekoriya-atelier"
```

Playground использует временную установку и SQLite. Это проверка реального выполнения PHP и фронтенда, не нагрузочный тест боевого хостинга/MySQL. Для полной матрицы темы на CI предусмотрен `php -l`.

## Редактирование контента

В этой стартовой теме доступны hero и контактная ссылка в Customizer. Основные разделы пока находятся в `template-parts/landing.html`; изображения и галереи — в `media.json` общего фронтенда. После изменения записей: `python3 tools/update-media.py`, затем повторная упаковка. Это явно ограниченный этап монтажа фронтенда; полноценный редактор всех разделов в WordPress пока не реализован.

Для следующей CMS-итерации: проекты как CPT `dekoriya_project`, услуги как страницы, направления/сезоны как таксономии, поля «объект, задача, фактический состав, исходные фото, результат». ИИ-концепции держать отдельным типом записей и никогда не смешивать с завершёнными кейсами. Hero и композиция остаются шаблоном, содержимое переносится в зарегистрированные блоки/поля. Картинки — в медиатеку с реальными attachment IDs и `wp_get_attachment_image`/srcset. Frontend motion подключается прежними файлами и селекторами.

## Дальнейшая SEO/GEO-структура

Главная остаётся входом. Первыми отдельными страницами: оформление входных групп, витрин и интерьеров. Затем — сезонные услуги и полноценные кейсы с собственными текстами, галереями и фактами. Страницы «Олеся и команда», «Контакты», полезные материалы и FAQ поддерживают экспертность и ответы в поисковых/генеративных системах.

Региональные страницы создавать только под подтверждённую географию и уникальный полезный материал. В паспорте и текущем тексте — Москва и область. Не размножать одинаковые страницы городов. До снятия noindex добавить реальный домен/canonical, контакты и реквизиты, sitemap и корректную schema по подтверждённым сущностям; рейтинги агрегатора автоматически в LocalBusiness не переносить. Аналитика и отправка заявок подключаются после определения получателя и выбранного канала; помощник текущего прототипа ничего не отправляет и не хранит контактные данные.
