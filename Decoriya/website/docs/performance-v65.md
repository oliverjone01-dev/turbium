# Производительность 6.5.0

В 6.4.4 первая анимация зависела от шести частей суммарным весом 469–651 КБ. Worker обрывал загрузку через 20 секунд, затем прямой проигрыватель пытался загрузить те же ресурсы с лимитом 12 секунд. На медленном соединении это могло завершаться статикой. Браузер также заранее загружал крупные невидимые фотографии.

## Изменения

Для первого поворота используется один компактный атлас: все 48 настоящих ракурсов, 192×144 на кадр. Размер — 150–182 КБ. Первое движение не требует Worker. Загрузка получает реальный прогресс; таймер сбрасывается при поступлении байтов и срабатывает только после 60 секунд отсутствия данных. Повторного скачивания тяжёлой серии при ошибке нет.

Полная серия 512×384 (384×288 на мобильном) догружается только после движения, если фактически измеренная скорость компактной загрузки выше 400 000 Б/с и не включён Save-Data. Она не блокирует компактный проигрыватель. Статичные конечные ракурсы остаются 1024×768; до загрузки открытого постера удерживается реальный последний кадр Canvas.

На слабой связи детальность движущегося растра ниже полной версии. Геометрия, все 48 ракурсов, порядок раскрытия и направление камеры сохранены. Это явный компромисс качества во время движения ради объёма передачи, а не обещание одинаковой детализации на любом соединении.

Графика hero получает отдельные мобильные размеры. WOFF2 сохраняет исходную гарнитуру и набор символов. Невидимые фотографии загружаются через IntersectionObserver с отступом 150 px; picture/source включаются только при приближении к экрану. Для выключенного JavaScript есть статичные изображения и страницы просмотра. Обычный просмотр галереи использует оптимизированный вариант 1280 px; исходные фотографии доступны только по явному выбору.

## Проверка

Локальный HTTP-сервер ограничивал **общую** скорость всех ответов 32 768 Б/с и добавлял задержку 150 мс. Кэш отключён; HTML/CSS/JS/SVG передавались с Gzip. Это контролируемая проверка реальной передачи ресурсов в браузер, а не физическая мобильная сеть.

- Холодный запуск витрины, десктоп: 10 883 мс от наведения до запуска проигрывателя, кадр 47 достигнут без ошибки.
- Холодный запуск входа, viewport 390 px: 11 850 мс, кадр 47 достигнут.
- Повторное наведение без скачивания: вызов запуска через 1 мс; сам переход длится 1800 мс. Это не измерение задержки физического экрана.
- Проверены реальные промежуточные кадры, закрытие при уходе курсора, мобильные варианты изображений и отсутствие горизонтального переполнения.

Подробные данные: `qa/performance-v65.json`. На таком ограничении первый поворот всё ещё требует ожидания. Мгновенная холодная загрузка не заявляется. PageSpeed/Lighthouse, полевые Core Web Vitals и реальные iPhone/Android в этой проверке не измерялись.

Для пересборки файлов: установить зависимости из `tools/requirements-assets.txt` в отдельное Python-окружение, выполнить `tools/optimize-assets.py`, затем `tools/update-media.py` и `tools/package-wordpress.py`. Для компактных атласов передать `--camera-render-dir` с исходными PNG renderer-а.
