# Приём заявок ДЕКОРИИ v10

Один HTTPS-приёмник для квиза и формы «Обсудим ваш объект». Подтверждение на сайте появляется после сохранения заявки, версии согласия и файлов в SQLite. Повтор с тем же ID не дублирует запись. Олеся открывает закрытую страницу `/inbox` с логином `olesya`. Уведомления в мессенджеры и письма не настроены.

## Развёртывание

- Выберите хостинг с постоянным диском в России и HTTPS. База и текст согласия должны лежать вне корня сайта и вне репозитория. Доступ к папке базы ограничьте учётной записью приложения. Настройте резервное копирование и срок удаления по согласованной политике.
- Установите зависимости в виртуальное окружение: `pip install -r requirements.txt`. Запуск за обратным прокси: `gunicorn --bind 127.0.0.1:8781 --workers 2 --timeout 45 'app:create_app()'`. Установите допустимый размер POST 51 МиБ на прокси. Прокси должен передавать источник запроса доверенным способом: в приложении лимит использует `REMOTE_ADDR`, поэтому на фронтовом прокси также нужен лимит на IP клиента. Сам WSGI-порт должен быть закрыт извне.
- Задайте `DEKORIYA_INBOX_DB`, `DEKORIYA_SITE_ORIGIN` (схема и хост без пути), `DEKORIYA_INBOX_PASSWORD` (секрет, 24+ символа), `DEKORIYA_CONSENT_FILE` (утверждённый текст UTF-8) и три публичных значения ниже.
- В GitHub Pages задайте переменные репозитория `DEKORIYA_LEAD_ENDPOINT` (HTTPS URL с путём `/lead`), `DEKORIYA_POLICY_URL`, `DEKORIYA_CONSENT_URL` и `DEKORIYA_CONSENT_VERSION`. Для WordPress задайте константы с теми же именами в конфигурации установки. Версия на странице и в приёмнике должна совпасть.
- После выкладки проверьте тестовую запись в закрытом кабинете и удалите её. Для регулярного удаления по сроку используется `python app.py --purge-before ISO_TIMESTAMP_UTC`.

Для локальной проверки `python app.py` слушает только `127.0.0.1`. Формы без подключения показывают рабочий телефон и отключённую отправку.
